# Метка под вопросом

**edinaya rossiya · КП2 · 5 ноября 2026**

Мультиагентный аудит текстовой разметки. На входе — обращения с уже выставленными метками и инструкция по классам. На выходе — очередь подозрительных строк, основания решений и журнал ручной проверки.

## Быстрый запуск

Нужен **Python 3.10+**. Для прототипа не нужны pip, Docker или база данных.

```powershell
python -m label_audit serve --open
```

Или откройте `START_DEMO.bat`. Интерфейс: http://127.0.0.1:8765. Нажмите **«Проверить разметку»**: учебный CSV уже выбран. Выберите обращение, проверьте цитату и соседей, подтвердите итоговую метку. Кнопки экспорта отдают рекомендации и CSV с подтвержденными человеком исправлениями. Исходник не перезаписывается.

## Что готово

- Пять отдельных агентов, общий JSON-контракт и оркестратор с ограниченной повторной проверкой.
- Локальный веб-интерфейс, загрузка CSV, поиск соседей, ручное решение, повторная проверка группы и экспорт.
- 120 синтетических обращений: 72 для разработки, 48 для проверки; парафразы одной семьи находятся в одной части.
- Воспроизводимая оценка, четыре способа ранжирования, модульные и HTTP-тесты.
- Адаптер совместимого Chat Completions API: лимит запросов, таймаут, один повтор при временной сетевой ошибке, кэш, проверка JSON, учет токенов.

**Предел готовности:** проверенный режим `demo` использует эвристики, а не LLM. Живой LLM-прогон в комплект не входит: при подготовке не было настроенного API или локальной модели. Проверки HTTP-адаптера используют тестовый сервер, а не настоящую модель. Качество на реальных обращениях и выигрыш мультиагентного подхода не доказаны.

## Воспроизвести результаты

```powershell
python -m unittest discover -s tests -v
python -m label_audit evaluate --out runtime/evaluation
python -m label_audit audit --input data/demo.csv --out runtime/demo
```

Сохраненные результаты КП2: `results/kp2_demo/metrics.json`. Новые запуски пишутся в `runtime/`, поэтому опубликованные результаты не перезаписываются автоматически. В `report.json` есть режим, версия и хеш инструкции, хеш входа, решения и журнал. `reviewed.csv` содержит только исправления, подтвержденные человеком.

| Метод, проверочная часть из 48 строк | Полезных случаев / 20 | Ошибочных меток / 20 | Recall внесенных ошибок @20 |
|---|---:|---:|---:|
| Случайная очередь, среднее 100 seeds | 7,46 | 4,11 | 0,411 |
| Противоречия соседей | 12 | 9 | 0,900 |
| Ключевые слова | 18 | 10 | 1,000 |
| Пять агентов, демо | 18 | 10 | 1,000 |

«Полезный случай» — внесенная ошибка или заведомо неоднозначное/непрофильное обращение. Поэтому 18/20 = 0,90 **не означает** 90% точности исправления меток: именно ошибочных меток найдено 10/20 = 0,50. В проверочной части всего 10 внесенных ошибок и 8 неоднозначных/непрофильных строк. На этом наборе пять агентов не лучше ключевых слов. Эти цифры — проверка конвейера на синтетике, не оценка LLM.

## Живая LLM

Определения классов и правила находятся в `data/taxonomy.json` (версия `1.1.0-kp2`),
промпты пяти агентов — в `PROMPTS` в `label_audit/provider.py`. В определениях есть
исключения и примеры: сбой оплаты относится к `payment`, сбой входа — к `account`,
отмена заказа и деньги после отмены — к `refund`. Просьба вернуть повторное списание
без отмены покупки остается `payment`. Причина и решение одной проблемы не создают
две темы; независимые нерешенные проблемы без явного приоритета передаются человеку.

Эти смысловые правила применяет LLM. Деморежим по-прежнему использует ключевые слова
и не интерпретирует отрицания, контекст или приоритет намерений. Обновление промптов
не является измерением качества модели: для сравнения нужен новый LLM-прогон на тех же
обращениях с той же моделью. Кэш учитывает полный промпт и таксономию во входе, поэтому
старые ответы для измененных запросов автоматически не используются. Сохраненные метрики
КП2 относятся к прежней версии инструкции.

Агент очереди получает готовый размер выборки (`selection_size`), краткую инструкцию
и список кандидатов. Для GigaChat JSON-схема дополнительно ограничивает ответ ID этих
кандидатов и нужным числом элементов. Ответ с повторными ID или неполной выборкой
не принимается. Размер ограничен бюджетом и числом переданных кандидатов.

Для семантического агента GigaChat схема ограничивает число меток и их допустимые ID,
длину цитаты длиной исходного текста, а обоснование — 320 символами. Оценка уверенности
выбирается из конечной шкалы от 0 до 1 с сохранением порога 0.65. Это ограничивает
разрастание ответа, включая длинную дробную запись числа. Системный промпт требует
короткий JSON без повторов. При finish_reason=length ошибка показывает настроенный
лимит и фактические входные/выходные токены, если API их сообщил. Это не устанавливает
причину обрыва: сообщение не приписывает его автоматически рассуждениям модели.
Усеченный ответ не используется и не кэшируется; автоматического увеличения лимита
или повторного запроса после такого обрыва нет.

Если API вернул пустой или некорректный ответ только на этапе агента очереди, готовые
решения проверяющих агентов сохраняются, а порядок ручной проверки строится локально.
Причина явно указывается в очереди и журнале; режим остается `llm`. Ошибки сети,
авторизации и квот продолжают останавливать запуск. Некорректные ответы не кэшируются;
сообщение об ошибке указывает агента и вид сбоя, не раскрывая текст ответа API.

Скопируйте `.env.example` в `.env` в корне проекта и задайте параметры своего доступного сервера. CLI и веб-сервер автоматически загружают этот файл независимо от текущей рабочей папки. Уже заданные переменные окружения имеют приоритет, включая пустые значения. После изменения `.env` перезапустите приложение. Файл `.env` исключён из Git.

```powershell
Copy-Item .env.example .env
```

Поддерживаются строки `KEY=value`, необязательный префикс `export`, одинарные и двойные кавычки, пустые значения и комментарии `#` (после значения — через пробел). Значения однострочные; подстановка переменных и escape-последовательности не выполняются. Параметры также можно задать через окружение:

Для уже запущенного Ollama:

```powershell
$env:LLM_BASE_URL = 'http://127.0.0.1:11434/v1'
$env:LLM_MODEL = 'имя-модели-из-ollama-list'
$env:LLM_TOKEN_PARAMETER = 'max_tokens'
python -m label_audit audit --mode llm --limit 8 --budget 5 --max-calls 40 --out runtime/live-smoke
```

Для совместимого облачного API:

```powershell
$env:LLM_BASE_URL = 'https://YOUR_PROVIDER/v1'
$env:LLM_MODEL = 'YOUR_AVAILABLE_MODEL'
$env:LLM_API_KEY = Read-Host 'API key' -MaskInput
$env:LLM_TOKEN_PARAMETER = 'max_completion_tokens'
python -m label_audit audit --mode llm --limit 8 --budget 5 --max-calls 40 --out runtime/live-smoke
```

`-MaskInput` доступен в PowerShell 7.1+. В старом PowerShell задайте переменную среды через настройки ОС. Не вставляйте ключ в код или репозиторий. У стороннего провайдера уточните поддерживаемое имя лимита токенов: `max_tokens` или `max_completion_tokens`. Требуются текстовый `system` и JSON mode; модель и тариф намеренно не зафиксированы без доступа к аккаунту.

Для OpenRouter можно задать `LLM_REASONING_EFFORT=none`, выбрав конкретную модель с отключаемыми рассуждениями. Случайный маршрутизатор `openrouter/free` может выбирать модели с обязательными рассуждениями: они тоже расходуют лимит `LLM_MAX_TOKENS`, даже когда итоговый JSON короткий. При остановке ответа приложение отдельно сообщает об исчерпании токенов и блокировке фильтром провайдера.

Для моделей OpenRouter с суффиксом `:free` запросы отправляются с интервалом не менее 3,1 секунды. Его можно изменить через `LLM_REQUEST_INTERVAL` (0–60 секунд). При временном HTTP 429 выполняется один повтор с учётом `Retry-After`, если ожидание не больше 60 секунд; при исчерпании суточной квоты повтор не выполняется. Успешные ответы сохраняются в кэше и используются при повторном запуске с теми же настройками и данными. Это не отменяет лимиты провайдера: для 120 обращений без кэша нужно минимум 242 вызова API, плюс проверки согласованности и возможные повторные проверки арбитра. Бюджет в интерфейсе ограничивает очередь человека, а не число вызовов API. Актуальные квоты: https://openrouter.ai/docs/api_reference/limits.

После успешной малой проверки:

```powershell
python -m label_audit evaluate --mode llm --max-calls 220 --out runtime/live-evaluation
```

Лимит считает все попытки, включая повторные запросы; это не денежный бюджет. Для оценки стоимости задайте фактические `LLM_INPUT_PRICE_PER_MILLION` и `LLM_OUTPUT_PRICE_PER_MILLION`. Если цены или usage неизвестны, стоимость равна `null`, а не нулю. Тексты отправляются только в явно выбранном режиме `llm`. Кэш хранит ответы локально в `runtime/cache`; для нового независимого опыта используйте новый каталог результатов или переместите свой кэш в архив.

## Структура

```text
label_audit/agents/      пять собственных агентов
label_audit/pipeline.py  общий сценарий и обратная связь
label_audit/provider.py  промпты, API, бюджет, кэш
label_audit/retrieval.py поиск похожих обращений
label_audit/web/         интерфейс
data/                   входные CSV и инструкция; без эталонов
evaluation/gold.json    эталоны, доступны только коду оценки
results/kp2_demo/        сохраненный эксперимент КП2
tests/                  проверка поведения агентов и интеграции
docs/                   архитектура, роли, защита, требования
output/                 отчет, презентация и снимки интерфейса
```

Исходная тема КП1 — поиск по учебным материалам. Для КП2 выбрана новая тема; это изменение отражено в отчете. Старые метрики RAG к аудиту разметки не применяются. Согласование смены темы с преподавателем не подтверждено.


## GigaChat

В `.env` задайте `LLM_BASE_URL=https://api.giga.chat/v1`, `LLM_MODEL=GigaChat-2`,
`LLM_TOKEN_PARAMETER=max_tokens`, `GIGACHAT_AUTH_KEY` (ключ авторизации из личного кабинета)
и `GIGACHAT_SCOPE=GIGACHAT_API_PERS` для физического лица. Очистите `LLM_REASONING_EFFORT`.
Для организации укажите scope своего договора (`GIGACHAT_API_B2B` или `GIGACHAT_API_CORP`).
Адаптер автоматически получает OAuth-токен и обновляет его перед истечением срока.
Ключи и токены не записываются в кэш. Проверка TLS включена; при необходимости задайте
`LLM_CA_BUNDLE` с путём к доверенному PEM-набору сертификатов.
После изменения настроек перезапустите сервер и выберите режим `llm`.
Документация: https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api.
