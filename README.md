# Метка под вопросом

**edinaya rossiya · КП2 · 5 ноября 2026**

Мультиагентный аудит текстовой разметки. На входе — обращения с уже выставленными метками и инструкция по классам. На выходе — очередь подозрительных строк, основания решений и журнал ручной проверки.

## Быстрый запуск

Нужен **Python 3.10+**. Для прототипа не нужны pip, Docker или база данных.

```powershell
python -m label_audit serve --open
```

Или откройте `START_DEMO.bat`. Интерфейс: http://127.0.0.1:8765. Нажмите **«Проверить разметку»**: учебный CSV уже выбран. Выберите обращение, проверьте цитату и соседей, подтвердите итоговую метку. Кнопки экспорта отдают рекомендации и CSV с подтвержденными человеком исправлениями. Исходник не перезаписывается.

## Что готово

- Пять отдельных агентов, общий JSON-контракт и оркестратор с ограниченной повторной проверкой.
- Локальный веб-интерфейс, загрузка CSV, поиск соседей, ручное решение, повторная проверка группы и экспорт.
- 120 синтетических обращений: 72 для разработки, 48 для проверки; парафразы одной семьи находятся в одной части.
- Воспроизводимая оценка, четыре способа ранжирования, модульные и HTTP-тесты.
- Адаптер совместимого Chat Completions API: лимит запросов, таймаут, один повтор при временной сетевой ошибке, кэш, проверка JSON, учет токенов.

**Предел готовности:** проверенный режим `demo` использует эвристики, а не LLM. Живой LLM-прогон в комплект не входит: при подготовке не было настроенного API или локальной модели. Проверки HTTP-адаптера используют тестовый сервер, а не настоящую модель. Качество на реальных обращениях и выигрыш мультиагентного подхода не доказаны.

## Воспроизвести результаты

```powershell
python -m unittest discover -s tests -v
python -m label_audit evaluate --out runtime/evaluation
python -m label_audit audit --input data/demo.csv --out runtime/demo
```

Сохраненные результаты КП2: `results/kp2_demo/metrics.json`. Новые запуски пишутся в `runtime/`, поэтому опубликованные результаты не перезаписываются автоматически. В `report.json` есть режим, версия и хеш инструкции, хеш входа, решения и журнал. `reviewed.csv` содержит только исправления, подтвержденные человеком.

| Метод, проверочная часть из 48 строк | Полезных случаев / 20 | Ошибочных меток / 20 | Recall внесенных ошибок @20 |
|---|---:|---:|---:|
| Случайная очередь, среднее 100 seeds | 7,46 | 4,11 | 0,411 |
| Противоречия соседей | 12 | 9 | 0,900 |
| Ключевые слова | 18 | 10 | 1,000 |
| Пять агентов, демо | 18 | 10 | 1,000 |

«Полезный случай» — внесенная ошибка или заведомо неоднозначное/непрофильное обращение. Поэтому 18/20 = 0,90 **не означает** 90% точности исправления меток: именно ошибочных меток найдено 10/20 = 0,50. В проверочной части всего 10 внесенных ошибок и 8 неоднозначных/непрофильных строк. На этом наборе пять агентов не лучше ключевых слов. Эти цифры — проверка конвейера на синтетике, не оценка LLM.

## Живая LLM

Откройте PowerShell в папке проекта и задайте параметры своего доступного сервера. Значения в `.env.example` — пример, файл автоматически не загружается.

Для уже запущенного Ollama:

```powershell
$env:LLM_BASE_URL = 'http://127.0.0.1:11434/v1'
$env:LLM_MODEL = 'имя-модели-из-ollama-list'
$env:LLM_TOKEN_PARAMETER = 'max_tokens'
python -m label_audit audit --mode llm --limit 8 --budget 5 --max-calls 40 --out runtime/live-smoke
```

Для совместимого облачного API:

```powershell
$env:LLM_BASE_URL = 'https://YOUR_PROVIDER/v1'
$env:LLM_MODEL = 'YOUR_AVAILABLE_MODEL'
$env:LLM_API_KEY = Read-Host 'API key' -MaskInput
$env:LLM_TOKEN_PARAMETER = 'max_completion_tokens'
python -m label_audit audit --mode llm --limit 8 --budget 5 --max-calls 40 --out runtime/live-smoke
```

`-MaskInput` доступен в PowerShell 7.1+. В старом PowerShell задайте переменную среды через настройки ОС. Не вставляйте ключ в код или репозиторий. У стороннего провайдера уточните поддерживаемое имя лимита токенов: `max_tokens` или `max_completion_tokens`. Требуются текстовый `system` и JSON mode; модель и тариф намеренно не зафиксированы без доступа к аккаунту.

После успешной малой проверки:

```powershell
python -m label_audit evaluate --mode llm --max-calls 220 --out runtime/live-evaluation
```

Лимит считает все попытки, включая повторные запросы; это не денежный бюджет. Для оценки стоимости задайте фактические `LLM_INPUT_PRICE_PER_MILLION` и `LLM_OUTPUT_PRICE_PER_MILLION`. Если цены или usage неизвестны, стоимость равна `null`, а не нулю. Тексты отправляются только в явно выбранном режиме `llm`. Кэш хранит ответы локально в `runtime/cache`; для нового независимого опыта используйте новый каталог результатов или переместите свой кэш в архив.

## Структура

```text
label_audit/agents/      пять собственных агентов
label_audit/pipeline.py  общий сценарий и обратная связь
label_audit/provider.py  промпты, API, бюджет, кэш
label_audit/retrieval.py поиск похожих обращений
label_audit/web/         интерфейс
data/                   входные CSV и инструкция; без эталонов
evaluation/gold.json    эталоны, доступны только коду оценки
results/kp2_demo/        сохраненный эксперимент КП2
tests/                  проверка поведения агентов и интеграции
docs/                   архитектура, роли, защита, требования
output/                 отчет, презентация и снимки интерфейса
```

Исходная тема КП1 — поиск по учебным материалам. Для КП2 выбрана новая тема; это изменение отражено в отчете. Старые метрики RAG к аудиту разметки не применяются. Согласование смены темы с преподавателем не подтверждено.
